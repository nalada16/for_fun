# 我的衣櫃電商頁面

這是一個手機優先的衣服收藏頁面。用逛電商的方式瀏覽自己的衣櫃，把想穿的加進購物車、完成下單，
重新發現那些已經擁有卻很久沒想起來的衣服。

線上瀏覽：https://nalada16.github.io/for_fun/

## 頁面

| 頁面 | 網址 | 內容 |
| --- | --- | --- |
| 首頁 | `#/` | 原本的衣櫃頁面（搜尋、分類、購物車、結帳、訂單紀錄、商品列表），加上每日推薦 |
| 今日穿搭 | `#/outfit` | 看今天天氣、選場合，隨機配一套穿搭 |
| 衣櫃分析 | `#/insights` | 衣櫃健檢、衣櫃統計、季節分析、衣櫃色盤 |

- 手機上選單固定在畫面底部；寬度 768px 以上改成頂部導覽列
- 用網址的 `#` 切換頁面，可以用瀏覽器的上一頁，也可以直接分享某一頁的網址
- 在衣櫃分析頁點某個顏色、季節或健檢項目，會回到首頁並直接捲到篩選好的商品
- 切換頁面時會記住首頁捲到哪裡，回來時回到原本的位置
- 商品列表依螢幕寬度排成 2／3／4／5 欄

## 特色

### 瀏覽與整理
- 手機版介面
- 可搜尋與分類（上衣／下身／洋裝／外套）
- 搜尋也會比對顏色、季節、風格等特徵，例如搜「優雅」、「冬」、「條紋」
- 可依價格排序、可隱藏已售出、可依顏色、季節或健檢項目篩選
- 每張卡片標出主色與適合的季節
- 點圖片看大圖

### 購物流程
- 可將喜歡的衣服加入「購物車」
- 結帳與訂單紀錄
- 可標記「已售出」（點一下或長按），已售出的不會再被加入購物車
- 消費金額統計：本月消費、累計消費、累計件數

### ✨ 每日推薦
每天自動挑 5 件衣服放在最上面。以日期作為亂數種子，所以同一天不管重新整理幾次都是同一組，隔天才會換一批。

挑選規則：
- 排除已售出的衣服
- **只挑當季的衣服**（當季不足 5 件時才放寬）
- **越冷門權重越高**：從沒被點開過的權重 ×3，點過越多次權重越低（`1 / (1 + 點擊次數)`）
- **最近 14 天推薦過的降權到 1/10**，避免一直推同幾件
- **每個分類最多 2 件**，不會五件全都是洋裝
- 從沒被點開過的會掛上「久違了」標籤

點圖片看大圖時會記錄瀏覽次數，這就是餵給推薦演算法的訊號。

以 169 件的資料實測：連續 14 天推薦 70 件次只重複 2 次（2.9%），90 天內有 167 / 169 件（99%）會被推薦到。

### 🎲 今日穿搭
一鍵隨機配一套：抽一件洋裝，或是上衣 + 下身，並算出這套的總金額。

- 已售出的不會出現
- 配色規則：一套最多一件鮮豔色，其他用中性或柔和色襯托

#### 🌡️ 依天氣挑厚薄
頁面上方顯示今天的天氣，預設台北，可以從選單換成其他縣市（會記住上次選的）。
天氣來自 [Open-Meteo](https://open-meteo.com/)，免費、不需要金鑰，也不需要開手機定位；
同一個城市一小時內只查一次。

用**體感溫度**對應每件衣服的厚度（metadata 的 `warmth`，1 最薄、5 最保暖）：

| 白天最高體感 | 上衣、下身、洋裝的厚度 |
| --- | --- |
| 28°C 以上 | 1–2 |
| 23–27°C | 2–3 |
| 17–22°C | 2–3 |
| 12–16°C | 2–4 |
| 12°C 以下 | 3–5 |

| 早晚最低體感 | 外套 |
| --- | --- |
| 26°C 以上 | 不加 |
| 20–25°C | 早晚溫差 8 度以上才加薄外套（厚度 2–3） |
| 15–19°C | 加薄外套（厚度 2–3） |
| 10–14°C | 一定加（厚度 3–5） |
| 10°C 以下 | 一定加厚外套（厚度 4–5） |

降雨機率 50% 以上會提醒帶傘。
天氣查不到（沒網路、服務暫停）時，自動改回依季節挑選：只挑當季的衣服，
外套機率夏天 15%、春天 50%、秋天 60%、冬天一定加。

#### 👔 場合模式
抽籤前可以選場合，用 metadata 的 `styles` 判斷一件衣服適合哪些場合：

| 場合 | 符合任一風格即可 |
| --- | --- |
| 不限 | — |
| 上班 | 正式、優雅 |
| 約會 | 甜美、優雅、復古 |
| 出遊度假 | 度假、休閒、日常 |
| 日常 | 日常、休閒、個性 |

上衣、下身、洋裝一定要符合場合；外套只要溫度對就好，有符合場合的外套會優先挑。
會記住上次選的場合；已經抽過一套時，換場合或換城市會直接重抽。

#### 配不出來時
依序放寬條件，並在結果上方寫出放寬了什麼：

1. 厚度範圍放寬一級（例如「符合今天溫度的衣服不多，放寬了厚度」）
2. 不看場合（例如「今天天氣適合「出遊度假」的衣服不夠，改從所有風格挑」）
3. 厚度再放寬
4. 從全部衣服挑

以現在 169 件的資料，從 2°C 到 34°C、每個場合各抽 200 次，都不需要放寬。

### 🩺 衣櫃健檢
衣櫃分析頁最上面的四張卡片，只計算還沒售出、而且有 metadata 的衣服。每個項目都可以點，會回到首頁列出那些衣服。

| 卡片 | 內容 |
| --- | --- |
| 重複最多的款式 | 同顏色、同袖長、同分類的衣服有 3 件以上的前三名，例如「黑色短袖上衣 8 件」 |
| 每一季能配出幾套 | 能互搭的上衣 × 下身組合，加上洋裝件數，並標出最少的一季 |
| 最難搭的衣服 | 找得到的搭配少於 10 件的上衣或下身；能搭配的定義是季節有重疊、而且兩件不同時是鮮豔色 |
| 你的風格 | 各風格的件數，最多的一兩種會寫成「優雅日常系」，並列出不到 10 件的風格 |

這裡只陳述衣櫃現況，不會出現「建議購買」之類的文字。

### 📊 衣櫃統計
總件數、衣櫃總價值、已售出比例，以及各分類件數的長條圖。

### 🎨 衣櫃色盤
每件衣服一個色塊，照色系和深淺排成一面色票牆，一眼就能看出衣櫃的顏色組成。
上方列出各顏色的件數，點顏色會篩選出那些衣服；點色塊可以看那件衣服的照片。

### 🌤️ 季節分析
春夏秋冬各有幾件衣服能穿，標出現在的季節和最缺衣服的季節。點季節一樣可以篩選。
季節依月份判斷：3–5 月春、6–8 月夏、9–11 月秋、12–2 月冬。

## 使用到的技術
- HTML5：頁面結構
- CSS3：響應式版型、卡片樣式、頁籤與按鈕樣式
- JavaScript：商品渲染、搜尋篩選、排序、購物車、結帳流程、訂單紀錄、已售出標籤、
  每日推薦演算法（以日期為種子的加權隨機抽樣）、依天氣與場合的穿搭組合、統計圖表、色盤、季節分析與衣櫃健檢
- JSON：商品資料（`data.json`）與衣服特徵（`metadata.json`）
- LocalStorage：保存購物車、訂單紀錄、已售出狀態、瀏覽次數、推薦歷史、城市與場合設定
- [Open-Meteo](https://open-meteo.com/)：今日天氣（免費、不需要 API 金鑰）
- GitHub Pages：靜態網站部署

## 使用方式
1. 把整理好的衣服資料填入 data.json。
2. 把衣服照片放到 assets/ 資料夾，並用連號命名（`0001.jpg`、`0002.jpg`⋯）。
   找不到對應圖片時會自動顯示 `assets/placeholder.svg`。
3. 網站會在 https://nalada16.github.io/for_fun/ 開啟。

### data.json 格式

```json
[
  {
    "id": "1",
    "name": "黑色龍鱗褶長褲",
    "category": "下身",
    "price": "NT$ 399",
    "note": "簡約日常，厚度適中，適合微涼天氣穿著。"
  }
]
```

`id` 會對應到 `assets/` 裡補零到四位數的圖片檔名，例如 `id: "1"` 對應 `assets/0001.jpg`。

### metadata.json：衣服特徵

顏色、季節這些分析用的是事先產生好的 `metadata.json`，網頁載入時直接讀取，不會每次重新分析。
`data.json` 還是手動維護的主資料，`metadata.json` 用相同的 `id` 對應。

目前的 169 件是由 Claude（Haiku）逐張看照片，再搭配名稱和備註標註出來的。
沒有照片的衣服只能從文字判斷，會標成 `"confidence": "low"`。

```json
{
  "1": {
    "color": "黑",
    "secondaryColors": [],
    "hex": "#1C1C1E",
    "pattern": "素色",
    "tone": "中性",
    "seasons": ["春", "秋", "冬"],
    "warmth": 3,
    "sleeve": "不適用",
    "styles": ["日常", "優雅"],
    "confidence": "high"
  }
}
```

| 欄位 | 內容 |
| --- | --- |
| `color` | 主色，只能從 16 色中選一個 |
| `secondaryColors` | 次要顏色，0–2 個 |
| `hex` | 照片中衣服主色的色碼，色盤用 |
| `pattern` | 素色／條紋／格紋／印花／圓點／拼色／漸層／其他 |
| `tone` | 中性／柔和／鮮豔，穿搭配色規則用 |
| `seasons` | 適合的季節，春夏秋冬可複選 |
| `warmth` | 厚度 1–5，從很薄透到很保暖，天氣穿搭用 |
| `sleeve` | 無袖／短袖／七分袖／長袖／不適用（下身） |
| `styles` | 1–3 個風格：日常、優雅、正式、甜美、休閒、復古、度假、個性，場合模式和健檢用 |
| `confidence` | 有看照片為 `high`，只看文字為 `low` |

每個欄位都限定只能從固定選項裡選，完整規則在 `tools/metadata/SPEC.md`。

**新增衣服之後：** 還沒有 metadata 的衣服照樣會顯示、也抽得到，只是不會出現在色盤和季節分析裡，
頁面會提示還有幾件沒有資料；天氣和場合也不會把它們排除。補的方法是請 Claude 依照 `tools/metadata/SPEC.md` 標註新的衣服、
加進 `metadata.json`，再執行驗證：

```bash
python tools/metadata/validate.py
```

它會檢查每個欄位是否符合規格、厚度與季節有沒有矛盾，並列出還缺 metadata 的衣服。

### 圖片輔助腳本
- `rename_images.py`：把圖片重新命名為連號
- `auto_rename_images.py`：自動依順序重新命名
- `remove_images.py`：刪除多餘的圖片

## 本地預覽

在這個資料夾執行：

```bash
python -m http.server 8000
```

然後打開 http://127.0.0.1:8000/

## 資料儲存說明

所有資料都存在瀏覽器的 LocalStorage，不會上傳到任何伺服器，換一台裝置或清除瀏覽器資料就會重來。
查天氣時只會把選的城市座標送給 Open-Meteo。

| Key | 內容 |
| --- | --- |
| `wishlist` | 購物車裡的衣服 id |
| `orders` | 訂單紀錄 |
| `soldItems` | 已標記售出的衣服 id |
| `viewCounts` | 每件衣服被點開看大圖的次數（推薦演算法用） |
| `recommendHistory` | 最近 14 天的每日推薦紀錄 |
| `sortOrder` / `hideSold` | 排序與篩選的偏好設定 |
| `weatherCity` | 今日穿搭選的城市 |
| `weatherCache` | 最近一次查到的天氣（一小時內有效） |
| `outfitOccasion` | 今日穿搭選的場合 |
